# The 1.0 Public API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the 0.10 option bag with the 1.0 API: languages by code, a style table per language, one `form` option, named cron flavours over explicit reading flags, instances built from chosen languages, a conformance export, and a translate-only cRonstrue adapter.

**Architecture:** Option handling splits in three. The core owns how a pattern is read (`src/core/reading.ts`). Each language owns its style table, regions and forms. The entry point (`src/cronli5.ts`) owns resolving a language code and rejecting what it cannot honour. Sentences do not change: no paradigm row's expected text is edited by this plan.

**Tech Stack:** TypeScript, Vitest with chai, tsd for type tests, eslint:all, `node --import tsx` for scripts.

**Spec:** `docs/superpowers/specs/2026-11-12-api-1.0-design.md`

## Global Constraints

- Work on a branch `api-1.0` cut from `renderer-process`. Never commit on `main`; never push or merge unless asked. `cli.js` carries the maintainer's own uncommitted mode change: after any `git add -A`, run `git reset -q cli.js` unless the task edits `cli.js`, in which case stage only the content change.
- `npm run verify` is the single gate and must pass at the end of every task.
- Lint rules are law: `opts` is the last parameter; `//` for prose, `/** */` only on exported declarations; named function expressions; no `undefined` literal; lines at most 80 characters.
- No process labels in shipped names or comments.
- A renderer never reads `pattern` or `shapes` (`test/lang/renderer-rules.js`). English's branch budget is 95 (`src/lang/en/status.json`); this plan may not raise it.
- **No expected sentence in `test/lang/en/paradigms/` changes.** Only the options objects on option rows are rewritten to the new names.
- No silent failure: an option the library cannot honour throws `Cronli5OptionError` with a message naming the fix. `lenient` never swallows it.
- Generated files are never hand-edited: run `npm run docs` after behaviour changes.
- Exact names from the spec: options `lang`, `style`, `form`, `cron`, `seconds`, `years`, `weekdaysFrom`, `questionMark`, `lenient`; forms `'fragment' | 'label' | 'sentence'`; flavours `'standard' | 'quartz'`; `questionMark` values `'reject' | 'allow' | 'require'`; style fields `hour12`, `short`; `create({languages, options, styles})`.

## Review Focus

1. A removed 0.10 option (`dialect`, `ampm`, `short`, `sentence`, `quartz`) passed at the top level: must throw naming its replacement, not be ignored. (Task 3)
2. `lang: 'EN-gb'`, `'en_GB'`, `'en-AU'`, `'xx'`: codes match case-insensitively with `_` or `-`; an unknown region falls back to the language; an unknown language throws even with `lenient: true`. (Task 3)
3. `weekdaysFrom: 1` under `cron: 'standard'` with `0`, `7`, `6L`, `2#2` and bare `L` in the weekday field: same numbering as today's Quartz mode, and `0` is an error. (Task 1)
4. A style given for one language while another is selected, through instance `styles` or a call's `style` with a field the language lacks: throws; never applies. (Tasks 2, 3)
5. The adapter given `?` in a day field with default options, and given `tzOffset: 0` or `verbose: false`: `?` reads as `*`; falsy forms of unsupported options are accepted. (Task 7)

### Task 3: The entry point: instances, language codes, `form`, and rejecting removed options

**Files:**
- Modify: `src/cronli5.ts`, `src/types.ts`, `src/browser.ts`
- Modify (options objects only): `test/lang/en/paradigms/options.js`, `test/lang/en/paradigms/hard-cases.js`, `test/lang/en/builder-cases.js`, `test/lang/options.js`, `test/lang/sentence.js`, `test/paradigms/check.js`, `tooling/scripts/edit-diff.mjs` (`optionsFor`), `tooling/scripts/metamorphic.mjs`, `scripts/docs.mjs`, `scripts/fuzz-lang.mjs`, `test/property/*`
- Test: `test/api/create.js`, `test/api/options.js` (new); the tsd type tests (`test-d/`)

**Interfaces:**
- Produces, from `src/cronli5.ts`:
  - `function create(setup: {languages: Cronli5Language[]; options?: Cronli5Options; styles?: Record<string, object>}): Cronli5`.
  - `default export`: `create({languages: [en]})`. Named exports: `create`, `Cronli5InputError`, `Cronli5OptionError`.
  - `interface Cronli5 {(pattern: CronPattern, options?: Cronli5Options): string}`: no methods.
  - `Cronli5Options`: `{lang?: string | Cronli5Language; style?: object; form?: 'fragment' | 'label' | 'sentence'; cron?: 'standard' | 'quartz'; seconds?: boolean; years?: boolean; weekdaysFrom?: 0 | 1; questionMark?: 'reject' | 'allow' | 'require'; lenient?: boolean}`.
- Resolution of `lang`: a module is used as given, with its default style. A string is split on `-` or `_`; the language part is matched case-insensitively against the instance's languages by `code`; the region part, upper-cased, selects `regions[region]`, else the default style. No match on language throws `Cronli5OptionError`: ``"cronli5 has no language 'uk' here. Import it (import uk from 'cronli5/lang/uk') and pass it as `lang`, pass it to create({languages}), or import from 'cronli5/all'."``
- Style for a call: `language.style(base, {...setup.styles?.[code], ...options.style})`.
- Any key of `options` (call or instance) outside `Cronli5Options` throws `Cronli5OptionError`. For `dialect`, `ampm`, `short`, `sentence`, `quartz` the message names the replacement from spec section 11.
- Consumes: `readingOf` (Task 1); `code`, `regions`, `style`, `label` (Task 2).

### Task 7: The cRonstrue adapter

**Files:**
- Create: `src/cronstrue/table.ts`, `src/cronstrue/index.ts`, `test/api/cronstrue.js`
- Modify: `scripts/build.mjs`, `package.json` (`./cronstrue` export), `scripts/docs.mjs` (generate the option table in `docs/migrating-from-cronstrue.md` from `table.ts`)

**Interfaces:**

Always `questionMark: 'allow'` and `form: 'label'`. An option name not in the table throws. Built on `src/all.ts`.
- Consumes: `cronli5/all` (Task 4).
