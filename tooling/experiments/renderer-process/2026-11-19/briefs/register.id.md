## Part 2: the reading check

`tooling/scripts/reading/run.mjs` renders every row of `conformance/id.json` as the sentence a user sees, picks moments to ask about (true firings and near-misses), and asks fresh readers briefed only in the language whether the task runs at each moment; answers are scored against an answer key that shares no code with the library (`oracle.mjs`). Read the header comments of `run.mjs` and `recheck.mjs`.

1. Run a sample first: `node --import tsx tooling/scripts/reading/run.mjs id --sample 40` (in the background if it takes long; these make model calls). Check the output parses (answers recognised as yes/no in this language) before spending on the full run. If answers are not recognised, fix the prompt entry's `yes`/`no` lists, nothing else.
2. Full run: `node --import tsx tooling/scripts/reading/run.mjs id` (default three readers). Run it in the background and wait for it; do not poll in a tight loop.
3. `node --import tsx tooling/scripts/reading/recheck.mjs id`: each question most readers got wrong is asked again alone of readers of two models.
4. Read `tooling/readings/id/report.md` and `recheck.md`. A question still misread alone by most readers of both models is a misreading of the description: a defect. For each, first check the answer key is right for that pattern (work the fire times by hand; a key bug is reported, not worked around). Then cure it test-first: the reason in the answers, the corrected sentence by hand in a row, watch it fail, then a general rule in the renderer. A cure must not lengthen other sentences; a wish for more words is not a cure. Questions misread by one model only, or only in a list, are notes: list them in `status.json`'s review text and your report, with the sentence. If you cannot cure a defect with a sentence you would sign as a native editor, stop on it and report the candidates.
5. After any cure: `npm run docs`, `npm run conformance`, `npm run verify` green again; re-run the reading check for the changed rows only if the script allows a sample that covers them, otherwise say they are unread.
6. Update `status.json` with the reading result in one sentence (rows, questions, share right, how many rechecked, how many still misread and what was done). Commit (`test(id): the reading check, and what it found`), report the hash. `tooling/readings/` is git-ignored; copy `report.md` and `recheck.md` to `SCRATCH/id-register/` for the orchestrator.
